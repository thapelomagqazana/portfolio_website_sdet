# 1. Product Definition

## 1.1 Product Name

**Thapelo Magqazana Engineering Portfolio**

## 1.2 Product Type

Personal professional portfolio and proof-of-work platform.

## 1.3 Product Purpose

The portfolio presents Thapelo Magqazana as a technically capable QA and Test Automation professional by combining:

- Professional QA experience
- Test automation capability
- Software development knowledge
- Certifications
- Engineering projects
- Technical thinking
- Evidence of practical work

The portfolio is designed to communicate professional capability faster and more convincingly than a traditional CV alone.

---

# 2. Product Goal

## 2.1 Primary Goal

Build a high-quality professional portfolio that converts recruiter and engineering-manager attention into meaningful professional opportunities.

The portfolio must demonstrate that Thapelo can:

1. Test software systematically.
2. Design and execute effective tests.
3. Automate repeatable testing activities.
4. Work with APIs, databases and CI/CD systems.
5. Understand software from a development perspective.
6. Investigate defects and communicate technical findings.
7. Build engineering tools and software.
8. Think about software quality as an engineering discipline.

---

# 3. Primary Audience

The portfolio has three primary audience groups.

Recruiters searching for candidates for:

- Software Tester

- QA Automation Engineer
- SDET
- Quality Engineer

- Current professional identity

- Automation capabilities

- Certifications

- How to contact Thapelo

> "Is Thapelo a credible candidate for a QA/Test Automation role?"

# 16. Content Principles

All portfolio content should be:

### Accurate

Never exaggerate experience, responsibilities or project maturity.

### Specific

Prefer concrete examples over generic claims.

### Evidence-based

Support important claims with work, screenshots, code, metrics or project links where possible.

### Concise

Respect the visitor's limited attention.

### Human

The portfolio should communicate Thapelo's personality and engineering journey.

### Technically credible

Avoid buzzwords without explanations or evidence.

# 18. Design Concept

## Concept Name

**The Engineering Lab**

## Design philosophy

> A personal engineering lab where software quality, automation and engineering thinking are demonstrated through real work rather than claimed through a résumé.

## Visual direction

> **Editorial minimalism + modern developer tooling**

The design should feel:

* Technical
* Precise
* Modern
* Calm
* Premium
* Human
* Accessible

Avoid:

* Cyberpunk aesthetics
* Excessive neon
* Generic developer imagery
* Excessive terminal interfaces
* Excessive animation
* Skill bars
* Fake statistics
* Technology-logo walls

# 22. Non-Functional Requirements

## Performance

Target:

* Lighthouse Performance ≥ 90
* LCP < 2.5 seconds
* CLS < 0.1
* INP < 200ms

Targets may be reviewed based on real production measurements.

## Accessibility

Target:

* Lighthouse Accessibility ≥ 90
* WCAG 2.2 AA-oriented implementation
* Keyboard accessibility
* Visible focus states
* Reduced-motion support
* Accessible colour contrast
* Semantic HTML

## Compatibility

Target:

* Chrome
* Edge
* Firefox
* Safari
* Modern Android browsers
* Modern iOS Safari

## Responsive Design

Supported viewport range:

> **320px → 1440px+**

# 23. Security Requirements

The portfolio must:

* Contain no secrets
* Avoid unnecessary data collection
* Use HTTPS
* Minimise third-party dependencies
* Keep dependencies updated
* Use appropriate security headers where supported

# 24. Content Boundaries

The portfolio must not:

* Invent employment achievements
* Invent client names
* Invent project users
* Invent revenue
* Invent adoption
* Claim QINIS is production-ready if it is not
* Claim BrikByteOS has users if this has not been demonstrated
* Claim senior-level experience without evidence

The portfolio should distinguish between:

> **Professional experience**

and:

> **Independent/ongoing engineering work**

# 25. Success Metrics

## Primary

### M1 — Professional clarity

At least **3/3 UAT participants** should correctly identify Thapelo's professional role after viewing the homepage.

Expected answer:

> QA Engineer / Test Automation Engineer.

### M2 — Project discoverability

At least **3/3 UAT participants** should locate QINIS and BrikByteOS without assistance.

### M3 — Contact discoverability

At least **3/3 UAT participants** should locate LinkedIn or email without assistance.

### M4 — Technical credibility

At least **2/3 technically knowledgeable reviewers** should report that the portfolio provides meaningful evidence of software/testing capability.

### M5 — Production quality

* Zero known P0/P1 defects at release.
* CI pipeline passes.
* Production build succeeds.
* Critical user journeys pass E2E tests.
